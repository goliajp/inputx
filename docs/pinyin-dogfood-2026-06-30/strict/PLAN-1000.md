## State management

Files:
- `articles_status.tsv` — 1 row per article, status fields
- `articles/{id}_{slug}.txt` — raw article text
- `segments/{id}.tsv` — linear typing plan
- `data/{id}.json` — dogfood query results
- `dashboard.html` — re-rendered

Status values:
- `TODO` — placeholder, no fetch yet
- `FETCHED` — article text saved
- `SEGMENTED` — typing plan written + coverage verified
- `IN_PROGRESS` — dogfood data file exists but not 100%
- `DONE` — 100% PASS
- `BLOCKED` — needs human attention (note)

Article ID convention: `{domain}{seq}` where seq is 3-digit sequence within domain.
e.g., `A001` = 政治第一篇, `B042` = 科技第42篇.

Override: existing `0001`-`0010` mapped to `A001`-`A010` (政治) — already DONE.

## Per-article workflow

1. **Fetch:** RSS / source URL → strip HTML → t2s (繁→简) → `articles/{id}_{slug}.txt`
2. **Segment:** LLM hand-segment per `feedback_segments_no_assembled_compounds`
   rules → `segments/{id}.tsv` + coverage assert (joined == cjk minus person-names)
3. **Build:** `tools/strict-dogfood/build_article_data.py {id}` → `data/{id}.json`
4. **Verify:** PASS rate. If < 100%, polish (modern_vocab or quickfix), rebuild.
5. **DONE** when PASS == total.

## Autorun cadence

`/loop 继续 autorun` 触发:
1. Read articles_status.tsv
2. Find next TODO → fetch
3. Move to next FETCHED → segment
4. Move to next SEGMENTED → build + polish
5. Update status, re-render dashboard, commit + push
6. ScheduleWakeup (30 min)

Stop conditions:
- 1000 articles DONE
- User flags an issue
- Repeated AUDIT failure on a single article (BLOCKED)
